## 58. 修正：游標在連結（或其他行內格式）結尾按 Enter 會留下空殼標記

- [x] 58.1 使用者回報：游標在一個連結（`<a>`）的最後面時按 `Enter`，會在下一行複製出「沒有連結但相同的內容」；以隔離測試伺服器重現：用真實的 DOM Range 將游標精確定位在連結文字節點的最後一個字元之後（等同使用者點擊/方向鍵移動到連結結尾時瀏覽器實際採用的游標表示法），觸發 `Enter` 後，下一行實際產生的是 `[](網址)`（空標籤文字、但保留原網址）——不是「內容重複」，而是「行內格式標記留下一個空殼」；用相同手法測試粗體/斜體/刪除線/醒目提示/行內程式碼，發現是同一類問題，皆會在下一行留下空殼標記（`****`／`` `` ``／`~~~~`／`====`）
- [x] 58.2 根本原因：`splitAtCaret` 透過 `Range.cloneContents()`／`setEnd`／`setStart` 對游標前後兩段內容分別複製節點；當游標精確落在某個行內格式元素（`<a>`／`<b>`／`<code>` 等）內文字節點的最後一個字元之後、且該元素是區塊裡最後的內容時，依照 DOM Range 規格，`afterRange` 的起點雖然「語意上後面沒有任何字元」，但其 `startContainer` 仍是該文字節點本身（容器不同於範圍終點），並不會被視為「已收合（collapsed）」的範圍；`cloneContents()` 因此依規格對這種「部分包含」的邊界情形，複製一份該行內格式元素的祖先鏈結構（內含空字串），而非回傳完全空的內容——這是瀏覽器 Range API 的規格行為，不是瀏覽器本身的錯誤，錯在本專案的 `htmlToInlineMarkdown` 沒有對「內文字為空的行內格式元素」做防呆，直接依原本邏輯序列化出 `[](網址)`／`****` 等空殼標記
- [x] 58.3 修正 `static/js/markdown.js` 的 `htmlToInlineMarkdown`：`A`、`CODE` 標籤與 `INLINE_WRAP_TAGS`（`B`／`STRONG`／`I`／`EM`／`S`／`STRIKE`／`DEL`／`MARK`）共用的包裝邏輯、以及字級調整 `SPAN` 的邏輯，皆改為「內文字為空時直接回傳空字串，不輸出任何包裝符號」；這是通用修正（不是只修連結），同時保護所有既有的行內格式在同樣的邊界情境下不再產生空殼標記
